      Network quality

      QualityDeviceLatencyJitterLoss ChecksBasis
      Measured with ICMP echo over the selected window, using the device and window chosen in Latency history above. Latency is the mean round-trip time of replies received. Jitter is the mean absolute difference between the average round-trip times of consecutive checks that both got replies (not RFC 3550 RTP jitter, and not one-way delay). Loss is probes without a reply as a share of probes sent. Time with no checks is a gap, never counted as 0 ms or as loss. A grade is the worst of the three figures against thresholds set in the inventory: application-level heuristics, not a QoS standard. This shows network performance; it does not verify or enforce QoS (DSCP marking, shaping or queueing).

      QoS telemetry (SNMP)

      Class / elementPackets/sThroughputDrops/s Drop %CountersUpdated
      QoS telemetry is what a device itself counts for a QoS policy element (a traffic class, a count action or a queue's dropper), read read-only over SNMPv3 through a documented adapter; the source MIB, adapter and counter width are shown for each device. It is not the Network quality grades above (those describe how ping behaved end to end), not the interface discards in the table below (those count everything dropped on a port, not one class or queue), and not DSCP markings observed in traffic (NetMonLT never inspects packets). Counters existing does not prove that QoS is enforced or effective. A dash means unknown, and hovering it says why: a rate needs two valid polls, so the first poll, a counter reset or a device restart has none. Drop % is shown only where one element counts both its traffic and its drops.
